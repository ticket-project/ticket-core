# ADR 0021: 주문은 본인이 선택 중인 좌석으로만 시작한다

## 상태

채택

[ADR 0001](0001-selection-and-hold-are-independent.md)의 "Selection 없이도, 남이 선택 중인 좌석으로도 주문할 수 있다"를 대체한다. Selection과 Hold를 다른 저장소·다른 수명으로
두는 구조는 그대로다.

## 배경

ADR 0001은 주문 생성이 Selection을 보지 않게 했다. 그 결과 두 가지가 가능했다.

- 회원 A가 좌석을 선택해 둔 동안 회원 B가 그 좌석으로 바로 주문하면 B가 이긴다. A는 화면에서
  골라 둔 좌석을 설명 없이 잃는다.
- 좌석 선택 화면을 거치지 않고 주문 API만 부르는 클라이언트(봇)가 선택 단계의 경합과 한도를
  건너뛴다. 좌석 선택 수를 회차 선점 한도로 제한해도, 주문이 선택을 보지 않으면 한도는 화면용
  장식에 그친다.

## 결정

예매 시작(`StartBookingUseCase`)은 요청한 좌석이 **모두 요청 회원이 지금 선택 중인 좌석**일 때만
Hold를 만든다. 아니면 409로 거절하고, 이유를 둘로 나눈다.

- `E4007`: 빠진 좌석이 모두 이 회원이 골랐다가 선택 시간이 지나 풀린 좌석이다. 사용자가 할 일(다시
  선택)이 분명해서 따로 안내한다(2026-09-29 추가).
- `E4006`: 그 밖의 경우. 선택한 적 없는 좌석과 다른 회원이 선택한 좌석은 구분하지 않는다 — 남의 선택
  사실을 응답에 흘리지 않는다.

만료를 알아보려고 회원별 선택 인덱스는 만료된 선택을 10분 더 남긴다. 직접 해제한 선택은 바로 지우므로
만료로 보이지 않고, 10분보다 오래 지난 만료는 `E4006`이 된다.

확인은 Hold를 만드는 좌석 락 안에서 한다. 선택·해제도 같은 좌석 락을 잡으므로 확인과 선점 사이에
다른 회원이 그 좌석을 고를 수 없다. 회원의 선택 좌석은 회원별 선택 인덱스에서 한 번에 읽는다.

Selection을 Hold로 **승격하지는 않는다.** 주문 성공 뒤 Selection을 정리하고 Hold를 따로 만드는 흐름,
Hold가 판매 정합성의 기준이라는 점은 ADR 0001 그대로다.

## 결과

- 좌석을 고른 뒤 선택 TTL(5분) 안에 주문해야 한다. 넘기면 다시 선택해야 한다.
- 좌석 경합은 주문보다 앞선 선택 단계에서 먼저 갈린다. 같은 좌석을 두 회원이 동시에 선택할 수
  없으므로, 같은 좌석의 동시 주문은 대부분 선택 단계에서 한쪽이 `E4001`로 떨어진다.
- 부하 테스트(`gatling-test`)도 주문 전에 좌석을 선택해야 한다. 사용자당 요청 수가 좌석 수만큼 는다.
