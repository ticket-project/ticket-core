# ADR 0022: 좌석 상태는 Lua 스크립트가 바꾸며 relay로 모든 인스턴스에 알리고, 만료는 Redis 만료 알림 없이 처리한다

## 상태

채택(2026-10-28). 2026-10-25의 제안("Redis 키 만료는 한 인스턴스만 처리한다", claim)을 대체한다. 결정의 근거와 고르지
않은 안 전체는 [스케일 아웃 결정 목록](../plans/scale-out-decisions.md) D2-1·D2-2와
[좌석 분산 락 다시 설계하기](../plans/seat-lock-redesign.md)에 있다.

## 배경

Core를 여러 인스턴스로 늘리려면 인스턴스 메모리 안에서만 맞는 동작을 고쳐야 했다.

- **좌석 상태 알림이 발행한 인스턴스 밖으로 나가지 않았다.** simple broker(`enableSimpleBroker("/topic")`)는 같은 JVM에
  붙은 STOMP 세션에만 보낸다. FE는 좌석 상태를 화면에 들어올 때 한 번만 읽고 그 뒤로는 WebSocket으로만 바꾸므로,
  다른 인스턴스에서 생긴 선택·선점·해제를 새로고침 전까지 못 본다.
- **Redis 키 만료 알림을 모든 인스턴스가 처리했다.** hold 메타 키 만료는 주문 만료를, 선택 키 만료는 "좌석 비었음"
  알림을 N번 돌렸다. 알림은 보내고 끝이라 구독이 끊긴 동안의 만료는 사라지고(주문은 5분 청소가 메웠다), 키를 실제로
  지울 때 나가 TTL보다 늦을 수 있다. 관리형 Redis는 기동 시 `CONFIG SET`이 막히고, 클러스터는 노드마다 구독해야 한다.
- **좌석 분산 락이 알림 순서를 지켰다.** 상태 변경과 발행을 같은 좌석 락 안에서 해서 "A의 만료 알림이 B의 선택 뒤에
  늦게 나가는" 역전을 막았다. 락을 잡는 Redis 왕복이 사용자당 약 21번 중 큰 몫이었다(추정).

## 결정

1. **좌석 상태를 바꾸는 일은 Lua 스크립트 하나가 확인·변경·알림 발행까지 한다. 좌석 분산 락을 쓰지 않는다.**
   선택(선점 확인 포함, 만료 장부 등록), 해제, 선택 만료 알림, 주문 선점(본인 선택 확인 포함), 선점 확정 알림(HELD),
   선점 해제(compare-and-delete, RELEASED)가 각자 스크립트 하나다. Redis가 스크립트를 하나씩 실행하므로 선택과 선점이
   엇갈리지 않고, 알림 순서가 상태가 바뀐 순서와 같다. 좌석 락 패키지(concurrency)를 지웠다.
2. **알림은 relay 채널 `seat:status:relay` 하나로 `PUBLISH`하고, 모든 인스턴스가 구독해 자기 STOMP 사용자에게
   보낸다**(`SeatStatusRelay`). 발행한 인스턴스도 구독으로 받는다. 전달은 인스턴스마다 단일 스레드, 큐 상한 없음이다.
   payload와 destination은 그대로다.
3. **주문 만료는 Redis 만료 알림 없이 DB 청소로만 한다.** 5초마다 모든 인스턴스가 돌고, 주문 한 건마다 트랜잭션을 열어
   `FOR UPDATE SKIP LOCKED`로 다른 인스턴스가 잠그지 않은 만료 주문 하나를 `EXPIRED`로 바꾼다. 순회당 상한은 없다.
4. **주문이 살아 있는지는 상태가 아니라 만료 시각으로 정한다.** 취소·상태 조회(그리고 결제를 붙이면 결제 확정)는 만료
   시각을 직접 비교한다. DB 상태 변경은 청소만 하되, 같은 회원·회차의 새 주문이 만료된 PENDING에 막혔을 때만 그
   자리에서 `EXPIRED`로 바꾼다. 결제는 승인까지 만료 시각 안에 끝나야 하고, 넘으면 결제를 취소한다.
5. **좌석 선택 만료 알림은 Redis 장부로 한다.** 선택 스크립트가 전역 Sorted Set `seat:select:expiry`(값 "회차:좌석",
   점수 Redis 시각 기준 만료 시각)에 함께 적고, 모든 인스턴스의 Worker가 1초마다 스크립트 한 번으로 최대 100개 꺼내며
   지운 뒤, 선택도 선점도 없는 좌석에만 `DESELECTED`를 보낸다. 선택권 자체는 선택 키 TTL이 푼다.

## 결과

- Redis 키 만료 알림(`notify-keyspace-events`)이 필요 없다. 관리형 Redis 설정과 클러스터 노드별 구독도 필요 없다.
- 서버 대수와 무관하게 모든 사용자가 같은 순서로 좌석 알림을 받는다. 주문 만료와 선택 만료 알림은 같은 일을 N번 하지
  않는다.
- 좌석 락 대기 실패(`E6003`)가 나지 않는다. enum은 `gatling-test`가 하드코딩하는 외부 계약이라 남겼다. 수용량 판정의
  과부하 신호는 다시 정해야 한다.
- 감수하는 것:
  - 주문 `EXPIRED` 반영과 `RELEASED` 알림이 최대 청소 주기만큼 늦다. 판매 정합성은 만료 시각 비교와 hold TTL이 지킨다.
  - Redis pub/sub은 최대 한 번 전달이다. relay 구독이 끊긴 동안의 알림과, 장부에서 꺼낸 뒤 알리기 전에 죽은 인스턴스의
    알림은 빠진다. FE를 고칠 수 없어 재조회로 메우지 못하고 새로고침까지 남는다.
  - 스크립트가 길어졌고, 경쟁 순서를 실제 Redis 통합 테스트로 고정해야 한다(`RedissonSeatSelectionStoreIntegrationTest`,
    `RedissonHoldStoreIntegrationTest`).
  - 전역 장부와 hold 메타 키에는 회차 hash tag가 없다. Redis Cluster로 가면 회차별 장부와 메타 키 hash tag로 바꿔야 한다.
- 다시 볼 때: 결제 후 자동 취소가 자주 생기면 결제 페이지 진입 때 hold 연장을, 청소 지연 지표가 커지면 주기·상한을,
  Redis Cluster로 갈 때 장부 구조를 다시 본다.

## 이력

- 2026-10-25: 제안 — relay와 claim(`SET NX`, 한 인스턴스만 만료 처리).
- 2026-10-26: relay·claim과 주문 만료 장부(Sorted Set + Worker)를 구현했다가 복잡하다는 이유로 되돌렸다.
- 2026-10-28: 위 결정으로 다시 정하고 구현했다.
