# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 소비할지 정한다.

## 탐색 전에 읽을 것

- **`CONTEXT.md`**(저장소 루트): 도메인 용어집. 이 저장소는 **단일 컨텍스트**라
  `CONTEXT-MAP.md`가 없다 — 없는 것이 정상이고, 없다는 사실 자체가 단일 컨텍스트라는 뜻이다.
- **`docs/adr/`**: 지금 손대는 영역에 걸리는 ADR을 읽는다. 언제 ADR을 쓰는지와 번호 규칙은
  `docs/adr/README.md`가 원본이다.

이 파일들이 없으면 **조용히 넘어간다.** 없다고 알리지 말고, 미리 만들자고 제안하지도 않는다.
`/domain-modeling`(`/grill-with-docs`와 `/improve-codebase-architecture`가 부른다)이 용어나
결정이 실제로 정해지는 순간에 만든다.

도메인 문서 밖까지 포함한 전체 목록은 `AGENTS.md`의 "먼저 읽을 문서" 표가 원본이다.
여기서는 도메인 문서만 다룬다.

## 파일 구조

```
/
├── CONTEXT.md          ← 용어집 (단일 컨텍스트)
├── docs/adr/           ← 되돌리기 어려운 결정
└── src/
```

## 용어집의 말을 쓴다

출력이 도메인 개념을 부를 때 — 이슈 제목, 리팩터링 제안, 가설, 테스트 이름 — `CONTEXT.md`가
정의한 말을 그대로 쓴다. 각 용어에 달린 `_Avoid_` 줄이 **쓰지 않기로 한 말**을 명시한다.
그쪽으로 흘러가지 않는다.

필요한 개념이 아직 용어집에 없으면 그 자체가 신호다. 이 프로젝트가 쓰지 않는 말을 지어내고
있거나(다시 생각한다), 진짜 빈틈이거나(`/domain-modeling`으로 넘긴다).

Bounded Context·Aggregate 경계와 모듈 배치는 용어집이 아니라 구조의 문제다 —
`CONTEXT.md`가 그 자리를 알려준다.

## ADR과 어긋나면 드러낸다

출력이 기존 ADR과 모순되면 조용히 덮지 말고 명시적으로 꺼낸다.

> _ADR-0001(선택과 hold는 독립)과 어긋나지만, 다시 열어볼 만한 이유는…_

뒤집기로 했으면 새 ADR을 쓰고 옛 ADR에 대체되었음을 적는다. 옛 ADR을 고쳐 쓰지 않는다.
