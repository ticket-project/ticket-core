# 관측된 실패

에이전트가 실제로 틀린 것과, **문서가 코드와 어긋나 에이전트를 틀리게 만들 것**을 여기 적는다.
추측으로 미리 막는 규칙은 여기 오지 않는다.

**lifecycle**: 문제 발견 → 여기 기록 → 재발 방지책을 canonical doc·Skill·executable test에
반영 → **반영되면 이 항목은 지운다.** 이 파일은 영구 지식베이스가 아니라 임시 inbox다. 해결된
기록을 남겨 두면 과거의 stale한 구조 설명이 영구히 agent context에 쌓인다.

## 어떻게 쓰는가

1. 에이전트가 틀리면 그 자리에서 고쳐 주고 끝내지 말고 여기 항목을 추가한다.
2. 무엇으로 막았는지 적는다. **문서 한 줄보다 테스트나 훅이 낫다.**
3. 문서에 규칙을 남겨야만 한다면 그 줄에 `[관측 YYYY-MM-DD]` 태그를 단다.
   `scripts/check-docs.sh`가 태그와 이 파일의 날짜를 대조한다. 짝이 없으면 CI가 실패한다.
4. **재발 방지책이 canonical doc·Skill·executable test에 반영되면 그 항목을 지운다.** 지우기
   전에 반영된 곳을 한 줄 남겨도 좋지만, 항목 자체를 영구 보존하지 않는다.

이 파일 자신의 헤딩은 `## <날짜> — <제목>` 형식을 쓴다(`[관측 ...]` 대괄호를 헤딩에 넣지
않는다) — `check-docs.sh` 검사 5가 다른 문서의 `[관측 YYYY-MM-DD]` 태그를 이 파일의
`^## YYYY-MM-DD` 헤딩과 대조하기 때문이다.
